# AI-assisted KiCad workflow

## Basis

The adopted project workflow is owner-directed: **Astra/Codex → Konnect MCP → KiCad 10 → deterministic validation → manufacturing outputs → human engineering review → physical prototype qualification**. The corpus includes older file formats as well as KiCad 10 files; conversion is never implicit authority to change unrelated design content.

KiCad references: [official IPC API](https://dev-docs.kicad.org/en/apis-and-binding/ipc-api/) and [KiCad 10 CLI manual](https://docs.kicad.org/10.0/en/cli/cli.html). The approved Konnect upstream is [mixelpixx/Konnect](https://github.com/mixelpixx/Konnect). A known-good reference stack was exercised on 2026-09-11 with KiCad/kicad-cli 10.0.6, Codex CLI 0.154.0, GPT-6 Astra and Konnect 0.11.1. See [TOOLCHAIN.md](TOOLCHAIN.md) for the operational setup, smoke tests, interaction model and upgrade rules. Exact patch versions are evidence for that reference environment, not a permanent substitute for capability verification.

## Requirements

- **FLOW-001:** Record KiCad exact version, Konnect upstream/version, Codex/model where AI is used, available capabilities, relevant library versions and execution environment before modifying a design. Confirm the active KiCad document and absolute project path before each editing session.
- **FLOW-002:** Prefer semantic KiCad/Konnect operations. PCB edits SHOULD use KiCad 10's official IPC API through Konnect when the required operation is supported. Capability discovery and a read-only smoke test MUST precede mutation after initial setup or a relevant tool upgrade; a tool name or product claim is not proof of coverage.
- **FLOW-003:** AI agents MUST NOT directly text-edit `.kicad_sch`, `.kicad_pcb`, `.kicad_pro`, `.kicad_sym`, `.kicad_mod`, `sym-lib-table` or `fp-lib-table`. If a required semantic operation is unavailable, stop and report the capability gap; use native KiCad under human control or improve/review the toolchain separately. Human-authored format-aware migration utilities remain a separately reviewed engineering activity and do not create an AI fallback permission.
- **FLOW-004:** Any approved schematic/library transformation MUST preserve unchanged UUIDs, symbol instances, hierarchical paths, sheet references, library IDs, pin types/numbers, net/label semantics and project integrity. New objects require valid unique identities. Regex replacement or parse success alone MUST NOT be accepted as electrical validation.
- **FLOW-005:** Work from a recoverable Git baseline. Save and reopen edited files in the selected KiCad version, inspect rendered sheets and board views, and compare connectivity and component mappings before and after. Resolve differences between in-memory state and saved files before validation or export.
- **FLOW-006:** Conversion of older projects to KiCad 10 MUST be an explicit reviewed step, with baseline comparison and library resolution. Conversion MUST NOT silently substitute parts or erase exclusions, net classes or fabrication settings. Avoid overwriting legacy references during unrelated changes.
- **FLOW-007:** Significant schematic edits MUST receive KiCad ERC. Significant PCB edits MUST receive KiCad DRC, applicable schematic parity and unrouted checks. Refill zones before final validation and use that same saved state for manufacturing generation. Follow [VALIDATION.md](VALIDATION.md).
- **FLOW-008:** Deterministic checks MUST record source commit/file hashes, tool versions, commands or semantic operations, settings, report locations, exit status and result disposition. Run checks against all affected projects, including users of changed shared libraries. Retain the human-facing evidence in the hardware PR/review record with durable links to any generated reports or artifacts.
- **FLOW-009:** A failed or partial operation MUST be inspected before retrying. Confirm whether it changed KiCad state; do not blindly replay non-idempotent edits. Avoid competing writers to one project.
- **FLOW-010:** AI-generated work MUST proceed through human electrical/manufacturing review and physical qualification. Human analysis SHOULD occur before layout and prototype ordering as well as after generated outputs are available. The workflow arrow does not postpone all engineering review until fabrication files exist.
- **FLOW-011:** Read-only audits MAY run on the default branch. Any AI-assisted design mutation MUST run on a dedicated task branch with a clean or intentionally scoped working tree. Do not let an agent create hardware changes directly on the default branch.
- **FLOW-012:** All KiCad path variables and shared-library mappings MUST resolve to the same repository revision being edited. A Git worktree MUST NOT use symbols, footprints, 3D models or templates from a different checkout. Until library resolution is reliably project-relative, prefer a task branch in the canonical checkout or deliberately repoint and verify the paths before using a worktree.
- **FLOW-013:** Use one mutation owner at a time. While Astra/Konnect owns a PCB editing phase, the operator MAY watch the live board but MUST NOT concurrently edit it. While Astra/Konnect owns a schematic editing phase, do not keep Eeschema open as a competing writer; use the Konnect schematic viewer or other read-only render for live observation.
- **FLOW-014:** Unattended audit sessions SHOULD use a read-only sandbox and explicit approval allowlist limited to non-mutating Konnect tools. Interactive design sessions SHOULD use approval-on-request. Mutation, routing, placement, delete, save, import and manufacturing-write operations MUST NOT receive blanket unattended approval merely for convenience.
- **FLOW-015:** For live PCB work, confirm the target board is open in KiCad and IPC is connected before mutation. Loss of IPC after a board was observed live, an `unsafe_file_fallback` condition or any uncertainty about in-memory versus saved state is a stop condition until the authoritative state is reconciled.
- **FLOW-016:** Schematic edits performed by Konnect's file-based semantic engine MUST be visually reviewed and ERC-checked before PCB synchronization. Significant schematic changes SHOULD receive a human checkpoint before layout proceeds.
- **FLOW-017:** Toolchain upgrades that can affect KiCad serialization, semantic editing, validation, libraries or manufacturing output SHOULD be isolated from unrelated hardware changes. Re-run the [TOOLCHAIN.md](TOOLCHAIN.md) smoke test and record the result before using the upgraded stack to mutate hardware.
- **FLOW-018:** Tool success, a clean Git diff, ERC/DRC success or successful manufacturing export MUST NOT by itself be interpreted as engineering approval, manufacturability acceptance, prototype validation or release qualification. Preserve the separate states defined by governance and qualification requirements.

## Session sequence

1. Create/select the task branch, confirm scoped Git state and establish the review record and intended change.
2. Read applicable requirements, baseline, board inventory, migration decisions and open questions. Confirm shared libraries resolve to the active checkout.
3. Record the exact toolchain and run the read-only Konnect/KiCad smoke test before mutation when required by FLOW-002/017.
4. Inspect connected designs, authoritative datasheets, sourcing state and mechanical assembly. Capture the current CAD and validation baseline.
5. Complete schematic decisions and semantic edits first where practical; inspect the rendered result, run ERC and obtain a human checkpoint for significant changes.
6. Update the PCB from the reviewed saved schematic through a supported semantic operation. Review any dry-run/plan before applying it.
7. Complete placement and obtain a placement checkpoint before substantial routing. Then route against reviewed fabrication/electrical constraints, not generic tool examples.
8. Refill zones, save the reviewed state, complete deterministic validation and disposition every relevant finding.
9. Generate and inspect manufacturing outputs for the same validated state; reconcile BOM/CPL/CAM/source and current JLCPCB sourcing requirements.
10. Obtain human electrical/manufacturing review and prototype-build acceptance; record physical test results and qualification state separately from development merge status.
11. Prepare release evidence and owner acceptance separately from merging development work.
