# Contributing

For the complete contributor workflow, see the [OpenHornet Contributing wiki page](https://github.com/jrsteensen/OpenHornet/wiki/Contributing). Discuss substantial new work in Discord or an issue before investing significant effort.

## Reporting and Tracking Work

Use the [GitHub issue forms](https://github.com/jrsteensen/OpenHornet/issues/new/choose) for work that belongs in the repository. Choose the issue type based on the purpose of the work:

- **Bug** — Something in the current design, documentation, or build is incorrect or broken.
- **Enhancement** — A new capability or intentional design change is proposed.
- **Obsolescence** — A purchased component is unavailable, end-of-life, or requires a supply-driven replacement.
- **Maintenance** — The desired design already exists, but repository artifacts need synchronization, migration, cleanup, consolidation, regeneration, replacement, or standardization.

Issue type and repository category are separate. Use **MCAD / Mechanical** for mechanical design work and **ECAD / Electrical** for PCBs, KiCad libraries, interconnects, and wiring. Interconnect is not a separate category.

Blank issues remain available for work that genuinely does not fit a form. When using one, provide enough current-state, desired-state, scope, and acceptance information for another contributor to act on it.

Link related issues and pull requests. When a pull request completes an issue, use a closing keyword such as `Closes #123`.
